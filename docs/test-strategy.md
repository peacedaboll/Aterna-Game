# Стратегия тестирования

**Проект:** Aterna  
**Движок:** Unity 2022.3.62f1  
**Версия документа:** 0.2  
**Дата обновления:** 11.10.2026

> Разработчик сообщил, что Windows-билд успешно создан. Запуск билда и прохождение всех сценариев не подтверждены в рамках этого аудита. Поэтому проверки запуска и игрового процесса остаются в статусе «Не проверено» до фактического прогона.

## 1. Цели

1. Проверить создание и запуск Windows-билда.
2. Проверить основной игровой маршрут: меню, выбор персонажа, карта, экран загрузки, локация.
3. Проверить движение, прыжок, коллизии и анимацию.
4. Находить регрессии после изменений кода и сцен.
5. Записывать результаты тестов и не обозначать непроверенные конфигурации как поддерживаемые.

## 2. Уровни тестирования

| Уровень | Объект проверки | Метод |
|---|---|---|
| Статическая проверка | Ошибки компиляции, ссылки компонентов, имена сцен, параметры Animator | Console, Inspector, Build Settings, просмотр кода |
| Модульное тестирование | Изолированная логика, если она вынесена в тестируемые методы | Unity Test Framework по мере развития проекта |
| Интеграционное | Кнопки, сцены, PlayerController, Rigidbody2D, Animator, коллайдеры | Ручной прогон в Editor и билде |
| Системное | Полный пользовательский сценарий | Сквозной тест от запуска приложения до уровня |
| Регрессионное | Ранее работавшие функции после изменений | Повторный прогон smoke-чек-листа |
| Сборка и запуск | Генерация Windows standalone и запуск приложения | Build Settings, запуск полученного билда |
| Совместимость | ОС, разрешения, оборудование | Матрица совместимости |

Автоматизированные тесты в репозитории не подтверждены. На текущем этапе основной подход — ручное тестирование с постепенной автоматизацией стабильной логики.

## 3. Критерии начала тестирования (Entry Criteria)

Тестирование начинается, если:
- проект открывается в Unity 2022.3.62f1;
- нет известных ошибок компиляции;
- зафиксирован commit или версия;
- выбран сценарий и определён ожидаемый результат;
- нужные сцены включены в Build Settings;
- для тестирования standalone сборка завершилась успешно.

Если сборка не создаётся, тестирование standalone блокируется. Ошибка сборки фиксируется отдельно, а запуск в Editor можно проверять независимо.

## 4. Критерии завершения тестирования (Exit Criteria)

Для smoke-теста текущего прототипа:
- билд запускается;
- главное меню отображается;
- основные переходы работают или каждый дефект зарегистрирован;
- персонаж двигается и прыгает ожидаемым образом;
- в Console/Player.log нет необъяснённых ошибок, относящихся к сценарию;
- все найденные дефекты имеют шаги воспроизведения и приоритет;
- матрица совместимости обновлена фактическими результатами.

Критический дефект в запуске или основном маршруте не позволяет считать smoke-тест пройденным.

## 5. Формат регистрации дефекта

| Поле | Что записать |
|---|---|
| ID | BUG-001, BUG-002 и далее |
| Дата и commit | Дата проверки и SHA/ссылка на commit |
| Среда | ОС, устройство, разрешение, Editor или standalone |
| Шаги воспроизведения | Последовательность действий |
| Ожидалось | Ожидаемое поведение |
| Фактически | Наблюдаемое поведение |
| Серьёзность | Blocker / Critical / Major / Minor |
| Доказательство | Скриншот, Console или Player.log |
| Статус | Open / In Progress / Fixed / Retest / Closed |

## 6. Чек-листы ручного тестирования

Для каждого пункта поставить один статус: **Пройдено / Не пройдено / Заблокировано / Не проверено**.

### 6.1. Smoke-тест Windows-билда

- [ ] Приложение запускается после сборки.
- [ ] Не появляется системное сообщение об ошибке при запуске.
- [ ] Главное меню отображается полностью.
- [ ] Кнопка Start реагирует на нажатие.
- [ ] Кнопка Exit закрывает standalone-приложение.
- [ ] Нет немедленного зависания или вылета.
- [ ] При наличии логов нет необъяснённых ошибок.
- [ ] Записаны дата сборки, версия/commit, ОС и разрешение.

### 6.2. Главное меню и выбор персонажа

- [ ] Menu открывается первой сценой.
- [ ] Start переводит в ChoiseCharacter.
- [ ] Доступный персонаж отображается и выбирается.
- [ ] Выбор персонажа открывает Traning.
- [ ] Нет ошибок загрузки сцены.
- [ ] Все видимые кнопки реагируют ожидаемым образом.

### 6.3. Карта, загрузка и локации

- [ ] Map открывается из соответствующего игрового маршрута.
- [ ] Узел Arama реагирует на нажатие.
- [ ] Узел Batava реагирует на нажатие.
- [ ] Узел CTown реагирует на нажатие.
- [ ] Если используется Load Scene, экран загрузки отображается ожидаемое время.
- [ ] Обратный отсчёт завершается.
- [ ] После отсчёта открывается ожидаемая сцена.
- [ ] Нет бесконечного цикла загрузки.
- [ ] После возврата на карту выбор остаётся работоспособным.
- [ ] Все переходы проверены именно в standalone-билде.

### 6.4. Управление и физика

- [ ] Персонаж движется влево.
- [ ] Персонаж движется вправо.
- [ ] При отпускании клавиш движение прекращается ожидаемым образом.
- [ ] Прыжок по Space работает с земли.
- [ ] Прыжок не срабатывает повторно в воздухе.
- [ ] После приземления прыжок снова доступен.
- [ ] Персонаж корректно сталкивается с землёй и платформами.
- [ ] Персонаж не проваливается сквозь платформы.
- [ ] Боковое касание объекта Ground не даёт нежелательного повторного прыжка.
- [ ] Управление восстанавливается после Alt+Tab и возврата в игру.
- [ ] Нет NullReferenceException от Rigidbody2D или Animator.

### 6.5. Анимация

- [ ] Animator назначен в Inspector.
- [ ] В Animator существует параметр isRunning типа Bool.
- [ ] Движение включает анимацию бега.
- [ ] Остановка выключает анимацию бега.
- [ ] Переходы состояний не застревают.
- [ ] Анимация не нарушает положение коллайдера.

### 6.6. Настройки и выход

- [ ] Окно настроек открывается.
- [ ] Окно настроек закрывается.
- [ ] Каждый видимый переключатель/ползунок влияет на ожидаемую настройку.
- [ ] Незавершённые функции не выглядят рабочими.
- [ ] Exit закрывает игру в standalone.
- [ ] Exit корректно останавливает Play Mode в Editor, если предусмотрено текущей реализацией.

### 6.7. Регрессия после исправлений

- [ ] Повторно выполнены шаги воспроизведения исправленного дефекта.
- [ ] Проверены связанные переходы между сценами.
- [ ] Проверено управление после изменений PlayerController.
- [ ] Проверено создание нового билда.
- [ ] Changelog обновлён фактическим изменением.

## 7. Приоритет тестирования

1. Запуск билда и меню.
2. Menu → ChoiseCharacter → Traning.
3. Map и переходы к Arama, Batava, CTown.
4. SceneDelayLoader и завершение загрузки.
5. Движение, прыжок, коллизии и анимация.
6. Настройки и остальные элементы интерфейса.
7. Разрешения и дополнительные аппаратные конфигурации.
